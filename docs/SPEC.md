# 연구 상태 엔진 — 구현 명세 v6 · 동결

> 이 문서는 제품 구현 사양의 단일 정본(SSOT)이다.
> 개발 운영 규칙은 저장소 루트의 `CLAUDE.md`를 따른다.
> 둘이 충돌하면 제품 사양에 대해서는 이 문서가 우선한다.

연구 상태 엔진 — 구현 명세 (v6 · 동결)
본선 현장에서 빈 저장소에 이 문서를 CLAUDE.md로 저장하고 시작한다. 코드·함수명·SQL은 없다. 무엇이 실제로 작동해야 하는가와 무엇으로 완료를 판정하는가만 있다.
목적은 검색 화면이 아니다. 연구자가 따로 기록하지 않아도 시도와 실패가 쌓이고, 그것이 다음 판단에 다시 쓰이는 것을 증명하는 것이다.

0. 절대 규칙
되돌릴 수 없는 동작은 사람 승인 없이 실행하지 않는다.
확실하지 않은 것을 확실하다고 표시하지 않는다.
조회 실패는 부재가 아니다. Crossref에서 못 찾았다는 것과 그 논문이 없다는 것은 다른 말이다.
연구자에게 기록을 요구하지 않는다. 저장 전에 확인을 받지 않는다. 불확실함은 저장을 막아서가 아니라 미상으로 남기고 판정에 쓰지 않는 것으로 처리한다.
하지 않은 일을 한 일로 기록하지 않는다. 계획·질문·가설은 시도가 아니다.
연구 상태·근거·판단·조회 캐시는 파일 하나로 끝나는 데이터베이스(SQLite) 에 담는다.
외부 연구 데이터 소스는 Crossref 공개 API 하나뿐이다. Claude·Gemini 등 LLM은 실행 계층이며 이 제한의 대상이 아니다.
조회 결과는 캐시한다. 캐시를 보여줄 때는 조회 시각을 함께 표시한다.
한 단계가 끝났다는 것은 화면에서 실제 값으로 확인됐다는 뜻이다.
완료 기준(§7)에 없는 기능은 만들지 않는다.
정상 입력뿐 아니라 잘못된 입력이 실제로 걸리는 것까지 확인한다.

1. 반드시 증명할 네 가지
A. 기록하지 않아도 남는다. "오늘 이렇게 해봤는데 여기서 멈췄다"고 말하면 저장 폼도, 확인 버튼도 없이 시도가 구조화되어 저장된다.
B. 남은 것이 다시 쓰인다. 다음 질문에서 그것이 검색되어, 같은 접근을 몇 번 해봤고 어디서 멈췄는지가 근거와 함께 나온다.
C. 근거가 바뀌면 과거 판단까지 표시된다. 근거가 나중에 철회되면 그 근거를 썼던 과거 판단에 재검토 표시가 소급해 붙는다.
D. 되돌릴 수 없는 것만 멈춘다. 그 하나가 대기 중이어도 다른 작업은 막히지 않는다.

2. 화면 3장
A. 연구 대화
연구자가 자연어로 묻거나 결과를 말한다.
답은 세 덩어리 : 이미 해본 것(같은 접근 N건 / 중단 단계 / 근거) · 근거 상태 · 다음 후보.
다음 후보의 근거에는 저장된 시도와 검증을 통과한 근거만 쓴다. 모델의 기억을 검증된 근거처럼 제시하지 않는다. 근거가 부족하면 경로를 지어내지 말고 "저장된 이력과 검증된 근거만으로는 다음 경로를 제시할 수 없습니다" 라고 밝힌다.
에이전트는 최종 결론을 대신 내리지 않는다.
B. 승인 대기열
승인이 필요한 동작만 카드로 쌓인다. 표시 : 하려는 작업 / 왜 승인이 필요한가 / 영향 대상 / 대상 파일의 현재 해시 앞 8자리.
버튼은 승인 / 거절. 승인 전에는 실제 실행이 일어나지 않는다.
승인 전 해시와 승인 후 해시를 같은 화면에 나란히 표시한다. 눈으로 비교되지 않으면 증명이 아니다.
승인 대기 작업이 남아 있어도 승인이 필요 없는 작업은 실행할 수 있어야 한다. 시연에서는 덮어쓰기 카드가 대기 상태인 동안 별도 분석 하나가 완료되어 결과가 화면에 추가되는 것으로 증명한다. 실제 동시 실행 여부는 이번 프로토타입의 검증 대상이 아니다. 비동기 큐·워커·동시성 구조를 만들지 않는다.
승인 필요 여부는 §10의 규칙표로 판정한다. LLM이 임의로 결정하지 않는다.
C. 연구 상태
자동으로 쌓인 시도 목록 : 대상 · 방법 · 환경 · 조건 · 결과 · 중단 단계 · 시각 · 원문 · 연결된 근거.
원문과 구조화 값을 함께 보여줘 어떤 흔적에서 만들어졌는지 확인할 수 있게 한다.
근거 상태 변경으로 영향받은 시도·판단에 눈에 띄는 표시.
상단에 [지금 재검사] 버튼 하나.
사후 수정과 수정 이력은 여력이 있을 때 구현한다(§8-7). 기본 요구가 아니다.

표기는 정해진 규칙으로 통일한다. 별칭은 시연 범위의 작은 사전만 쓴다.

값이 없으면 추측하지 않고 미상으로 둔다.

실행 여부가 불명확하면 이미 실행한 것으로 추측하지 않는다.
이 규칙이 없으면 시스템의 유일한 자산인 실패 이력이 스스로 오염된다.
자동 축적의 안전장치
저장 자격을 통과한 것은 별도 확인을 요구하지 않고 자동 저장한다. 저장 직후 화면에 한 줄로 보여준다.
"자동 기록됨 — 대상 ○○ / 방법 ○○ / 환경 ○○ / 결과 ○○"
대상·방법·환경 중 하나라도 미상이면 같은 접근 판정에 쓰지 않는다.
안전성은 저장을 막아서가 아니라, 불확실한 값을 판정에 쓰지 않는 것으로 확보한다.

4. 같은 접근인가 — 이번 프로토타입의 운영 규칙
전 분야에 통하는 "시도의 본질"을 정의하려는 것이 아니다. 반복 접근을 찾기 위한 이번 시연의 운영 규칙이며, 분야에 따라 달라질 수 있다.
대상 + 방법 + 환경을 같은 접근을 묶는 키로 쓰고, 조건은 그 안의 변주로 본다.

입력에 DOI만 있고 비교할 서지가 없으면 서지 일치를 주장하지 않는다. 레코드 확인 사실과 Crossref에 등록된 제목·저자·연도를 그대로 보여준다.
확인 불가는 화면에서 하나로 두되 사유를 내부에 구분 저장한다. 화면 문구 예:

 "DOI 등록을 확인하지 못했습니다. 제목·저자 기준으로 추가 확인이 필요합니다."



표기·대소문자·공백 차이는 통일한 뒤 비교한다. 형식 차이는 불일치로 보지 않는다.
철회 판정은 관계의 방향과 유형을 구분한다. 철회 유형인 관계만 철회로 본다. 출처도 저장한다.
조회 실패 처리 — 실패가 기존 사실을 지우지 않는다
과거에 정상 조회된 기록이 있는데 최신 조회만 실패한 경우, 기존 근거 상태를 확인 불가로 덮어쓰지 않는다.
기존 상태를 유지하고 화면에 최신 확인 실패 · 마지막 확인 YYYY-MM-DD HH:MM 을 따로 표시한다.
과거 기록도 캐시도 전혀 없는 상태에서 최초 조회까지 실패했을 때만 확인 불가 · 사유: 조회 실패로 기록한다.
잘못된 근거를 지우지 않는다
확인 불가·서지 불일치가 나와도 기록은 남긴다. 판단에 쓰는 근거 집합에서만 제외하고 이유를 한 줄 남긴다.

6. 근거와 판단 연결 · 소급 재검사
모든 판단에 사용한 근거를 연결해 저장한다. 근거 → 판단을 역방향으로 따라갈 수 있어야 한다.
판단에 저장할 것 : 질문 / 시각 / 사용한 시도 / 사용한 근거 / 제안 / 이후 연구자의 행동.
[지금 재검사]
저장된 근거를 캐시를 건너뛰고 새로 조회한다.
새로 철회된 것은 철회됨으로 바꾼다.
그 근거에 연결된 과거 판단을 역으로 찾아 근거 상태 변경 · 재검토 필요 표시를 붙인다.
조회에 실패하면 캐시를 새 정보인 척 쓰지 않고 위 §5의 조회 실패 처리 규칙을 따른다.
소급을 시연하는 방법 — 시간 압축
지금 철회된 논문을 처음 조회하면 처음부터 철회됨이라 상태 변화가 없다. 그래서:
아밀로이드 논문(2006년 발표, 2024년 6월 철회)을 근거로 쓴 판단 하나를 철회 이전 시점 상태로 미리 저장한다. 당시 근거 상태는 확인.
화면에 "철회 이전 시점의 시연용 과거 상태" 라고 표시한다.
[지금 재검사] 를 누르면 현재 Crossref 조회로 철회가 확인되어 확인 → 철회됨 변화가 발생하고, 연결된 과거 판단에 재검토 표시가 새로 붙는다.
가짜 철회를 만드는 것이 아니라 실제로 일어난 2024년 철회를 시간 압축해 재현하는 것이다.

7. 완료 기준 — 여섯 줄
자동 축적 — 연구자가 자연어로 실행 결과를 말하면 별도 저장·확인 입력 없이 시도가 구조화되어 저장되고 화면 C에 새 줄이 생긴다. 구조화 결과와 원문이 함께 보인다. 계획·질문만 말했을 때는 저장되지 않는다.
재사용 — 시작 시 같은 접근의 과거 시도가 2건 있다. 연구자가 세 번째 결과를 말하면 즉시 3건이 되고, 그 뒤 질문하면 "이 접근은 3번 시도됐고 모두 ○○ 단계에서 멈췄습니다"가 저장된 3건을 근거로 표시된다.
근거 양방향 — 정상 DOI는 확인, 손상 표본은 서지 불일치, Crossref에서 확인되지 않는 DOI는 확인 불가로 각각 실제로 나온다. 확인 불가를 "존재하지 않음"으로 쓰지 않는다.
철회와 소급 — 실제 철회 논문이 철회됨으로 확인되고, 철회 이전 시점의 시연용 과거 판단에서 [지금 재검사] 를 누르면 확인 → 철회됨 변화와 함께 그 판단에 재검토 표시가 새로 붙는다.
게이트 실증 — 원본 덮어쓰기를 요청하면 대기열로 가고, 승인 전 해시와 승인 후 해시가 화면에 나란히 보이며 승인 전에는 변하지 않는다. 대기 중에도 승인이 필요 없는 분석 하나가 완료되어 결과가 추가된다.
영속성 — 앱을 껐다 켜도 자동 축적된 시도 · 근거 · 근거와 판단의 연결 · 철회 상태 · 이미 붙은 소급 표시가 그대로 남아 있다.
★ 1번이 이 프로토타입의 존재 이유다. 시간이 부족해도 삭제하지 않는다.

8. 구현 순서
데이터 구조 + 시연 데이터 + 화면 C 최소 표시
자동 축적 — 자연어 → 저장 자격 판정 → 추출 → 자동 저장 → 화면 C 새 행 + "자동 기록됨" 한 줄
같은 접근 / 완전 반복 / 인접 / 미확정 판정 → 화면 A

9. 시연 데이터 — 성격을 나눈다
A. 기관 시도 이력 — 합성 데이터
시도 이력 6~8건은 시연용 합성 데이터다. 그중 같은 접근의 과거 시도 2건을 미리 둔다. 대상·방법·환경 동일, 조건은 서로 다름, 중단 단계 동일.
B. 근거 문헌 — 실제 공개 데이터
정상 DOI 1건
서지를 일부러 손상시킨 표본 1건 — 저자·연도는 그대로 두고 제목만 명백히 무관한 것으로 바꾼다. 화면에 "시연용으로 일부러 손상시킨 표본"이라고 표시한다.
Crossref에서 확인되지 않는 DOI 1건 — 형식이 깨진 문자열이 아니라 DOI 형태는 정상인 테스트 값
실제 철회 논문 1건 (아밀로이드 사례)
시드에 넣지 않은 정상 DOI 1건 — 발표 중 현장에서 직접 입력해 하드코딩이 아님을 보이는 용도
표시
화면과 발표자료에 "기관 시도 이력은 시연용 합성 데이터 · 문헌 근거와 철회 정보는 공개 실제 데이터" 를 표시한다.

11. 시연 초기화 규칙 — 리허설이 데모를 망가뜨리지 않게
라이브를 반복하면 2건이 3건, 4건, 7건이 되고 소급 표시는 이미 붙어 있으며 테스트 원본 파일도 이미 바뀌어 있다. 반복 자체가 초기 조건을 파괴한다.
제품 기능으로 초기화 버튼을 만들지 않는다. 이건 기능이 아니라 운영 절차다.
기능 동결 직후, 시연 시작 상태를 별도 사본으로 고정한다.
baseline 데이터베이스 : 같은 접근 과거 시도 2건 + 철회 이전 판단 상태
baseline 원본 파일 : 승인 게이트 테스트 전 상태
일반 근거는 사전 조회 캐시를 준비한다.
★단, 소급 시연에 쓸 철회 논문의 현재 Crossref 응답은 baseline 캐시에 넣지 않는다. 넣으면 버튼을 누르기 전에 이미 철회 상태가 되어 인과가 깨진다. 이 논문은 [지금 재검사] 때 캐시를 우회해 현재 Crossref를 처음 조회하게 한다.
각 리허설과 본 발표 직전에 baseline 사본으로 복원한다.
복원 뒤 네 값을 확인한다. 하나라도 맞지 않으면 시연을 시작하지 않는다.
같은 접근 = 2건
과거 판단의 근거 상태 = 확인
소급 재검토 표시 = 없음
승인 테스트 원본 해시 = 기준 해시

13. 진행 규칙
화면에서 실제 값이 확인된 단계만 커밋한다. 커밋 메시지에 단계 번호를 쓴다.
한 방법이 두 번 실패하면 반복하지 말고 경로를 바꾼다. 막힌 이유를 한 줄 남긴다.
검사 대상이 0건이면 통과로 보지 않는다. 통과 N / 전체 M을 함께 남긴다.
정상 표본과 손상 표본을 모두 검사한다. 계획 발화가 저장되지 않는 것도 검사 대상이다.
긴 출력은 대화에 붙이지 않고 파일로 남기고 경로만 말한다.
기능 동결 이후에는 시연이 깨지는 경우 외에 손대지 않는다.

부록. 시연 중 문제가 생겼을 때 할 말 — 두 가지를 구분한다
외부 조회가 실패했을 때 (우리 시스템은 정상)
"Crossref 최신 조회가 지금 실패했습니다. 그래서 시스템이 확인됐다고 말하지 않고 마지막 확인 시각이 붙은 기존 상태를 그대로 표시합니다. 확인하지 못한 것을 확인했다고 말하지 않는 것이 이 시스템의 원칙입니다."
우리 프로그램이 깨졌을 때
"라이브 실행에 문제가 생겨 백업 화면으로 전환하겠습니다. 동일한 흐름을 사전 실행 결과로 보여드리겠습니다."
★두 번째 상황에서 첫 번째 문장을 쓰면 거짓말이 된다. 변명하지 말고 바로 전환한다.
심사위원에게 DOI를 청하지 않는다. 시연 중 대표가 직접 시드에 없는 DOI를 입력해 하드코딩이 아님을 보인다. 질의응답에서 먼저 제안하지 않고, 물어보면 그때 조회한다.
